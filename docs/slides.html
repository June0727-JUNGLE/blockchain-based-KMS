MultiSig-KMS

블록체인 기반 분산 키 관리 시스템

암호화된 기밀 데이터의 복호화 권한을
2-of-3 멀티시그로 통제하는 하이브리드 KMS

배경 및 문제 정의

  • 기존 KMS는 마스터 키·권한 DB가 한곳에 집중 → 단일 실패 지점(SPoF)
  • 중앙 DB 접근 로그는 내부자에 의해 조작될 수 있음
  • 지갑·계정 탈취 시 즉시 권한 회수가 어려움
  • 모든 문서에 동일한 결재 절차 → 운영 비용·UX 저하

"비밀 파일을 체인에 올리지 않고, 누가 열 수 있는지만 분산 통제한다."

프로젝트 목표

  • 하이브리드 데이터는 오프체인, 권한은 온체인
  • 차등 통제 일반 문서 vs 보안 문서 tier 분리
  • 멀티시그 보안 문서는 결재권자 3명 중 2명 승인
  • 감사 모든 접근·결재·권한 변경을 불변 이벤트로 기록
  • 시연 MetaMask + app.html 단일 dApp으로 실제 동작 검증

일반 vs 보안 문서

📄 일반 문서 (normal)

사내 공지, 인사 규정 등

  1. logDocumentAccess tx
  2. 감사 기록만 (결재 없음)
  3. 즉시 plain 텍스트 열람

🔒 보안 문서 (secure)

차량 텔레메트리 로그 등

  1. requestDocumentAccess
  2. Approver 2명 approveAccess
  3. DocumentAccessed 후 AES 복호화

보안 문서 접근 시퀀스

Admin
grantPermission → 직원
request → Approver ×2
approve → DocumentAccessed → KMS 서버
복호화
  • 온체인: 허가서 발급 (DocumentAccessed = 복호화 권한 확정)
  • 오프체인: receipt·이벤트 검증 후에만 파일 반환 (미승인 → 403)

오프체인 KMS 서버

  • GET /api/documents — manifest 기반 문서 목록
  • POST /api/open — txHash + 온체인 이벤트 검증 후 내용 반환
  • verify.js — DocumentAccessLogged / DocumentAccessed 재검증
  • decrypt.js — AES-256-GCM 복호화 (storage/encrypted/)
